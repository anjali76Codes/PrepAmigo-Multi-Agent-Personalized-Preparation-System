# Study Materials Generation Pipeline

This document explains how the **Assessment Agent** and **Flashcard Agent** work in the PrepAmigo system, including their generation logic, database architecture, and evaluation pipeline.

## 1. Overview
When a `StudyPlan` is generated by the Planner Agent, each Sprint contains a number of `SprintDays` (usually 6 days per sprint). To prevent overwhelming the user with daily quizzes and flashcards, the generation pipeline intelligently **chunks the days**.

## 2. The 3-Day Chunking Logic
Rather than generating 1 Assessment and 1 Flashcard set per day, the agents compress the learning objectives dynamically.
- The pipeline iterates over `SprintDays` in chunks of 3.
- If a sprint has 6 days, it creates two chunks: **Days 1-3** and **Days 4-6**.
- The `topic_titles` and `objectives` for all days in a chunk are merged, deduplicated, and sent as a single prompt to the LLM.
- **Output**: The LLM generates exactly **1 Assessment (10 questions)** and **1 Flashcard Set** to comprehensively cover that entire 3-day block.

## 3. Database Architecture (MongoDB)
The generated data is directly inserted into the MongoDB cluster, maintaining strict relational links for easy frontend querying.

### Assessment & Flashcard Schemas
Instead of holding a single `sprint_day_id`, these models store:
- `sprint_id`: Reference to the parent Sprint.
- `covered_sprint_days`: An array `[ObjectId]` containing the IDs of all 3 days the document covers.

### SprintDay Linking
Once an Assessment and Flashcard set is inserted, the pipeline performs an update on all 3 `SprintDay` documents in that chunk, setting their `assessment_id` and `flashcard_id` fields.

**Frontend Benefit**: When the frontend requests any single Sprint Day (e.g., Day 2), it can simply use Mongoose's `.populate("assessment_id")` and `.populate("flashcard_id")` to instantly load the full 3-day quiz and flashcards without any extra database queries.

## 4. LLM-as-a-Judge Evaluation Pipeline
To ensure the LLM generates high-quality, relevant materials without hallucinating, an automated evaluation script is included. 

### `evaluate_generation.py`
This script acts as a strict Educational AI Evaluator. It pulls the generated Assessments and Flashcards from the database, compares them against the original `SprintDay` objectives, and generates a detailed Markdown report (`evaluation_report.md`).

**What it evaluates:**
1. **Coverage Analysis (0-100%)**: Did the generated questions actually test all the requested objectives?
2. **Relevance Analysis (0-100%)**: Did the LLM stick to the topic, or did it hallucinate out-of-scope concepts?
3. **Quality Analysis (0-100%)**: Are the questions intellectually stimulating and requiring critical thought?

### Running the Evaluation
To evaluate the latest generation in your database:
```bash
python src/scripts/evaluate_generation.py
```
This will produce a highly detailed `evaluation_report.md` file in the root directory, which can be showcased to demonstrate the system's focus on AI accuracy, quality control, and hallucination mitigation.
